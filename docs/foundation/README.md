# Foundation Documents

This folder holds the system-wide facts every later PRD, ADR, and C4 diagram
is allowed to assume without re-deriving: what CryptoSandboxQA is, who it's
for, what its core domain terms mean, and how its top-level pieces relate.

**Owner:** Human-maintained (no toolkit owns this layer yet — see note below).

**Contract these documents follow:**
- They describe **facts about the existing system**, sourced from
  [`ARCHITECTURE.md`](../../ARCHITECTURE.md), [`CLAUDE.md`](../../CLAUDE.md),
  and [`FEATURES_INVENTORY.md`](../../FEATURES_INVENTORY.md) — not invented.
- They do **not** contain product requirements (that's a PRD's job) or
  architecture decisions/trade-offs (that's an ADR's job).
- Every later PRD or ADR should reference these instead of re-explaining what
  a "User", "Wallet", or "Order" is.

## Why this exists as a separate layer

Neither `product-toolkit` (produces PRDs — requirements) nor
`architecture-toolkit` (produces ADRs/C4 — design decisions) is responsible
for descriptive system facts; both assume that context already exists. These
documents were written directly (not generated by a toolkit skill) because no
skill currently owns this layer. If this pattern recurs across projects, it's
a candidate for a dedicated Foundation Toolkit — but that's a separate,
larger effort from producing this content once, here.
